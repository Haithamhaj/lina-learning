# Lina Educational Visuals — canonical visual grammar v1

Authority: LINA-VISUAL-INTELLIGENCE-01, derived from accepted STUDIO-VISUAL-PROCESS-01.
This is the source of truth for educational visual composition within existing
product, child-safety, Studio and Learning Intelligence boundaries. It is not a
new renderer protocol or permission to enable a planned pattern.

## Separate responsibilities

| Responsibility | Owner and boundary |
|---|---|
| Pedagogical representation | Primary Tutor expresses whether/what visual helps the current question. Books ground facts; they do not permit or forbid learning. |
| Development | Codex/engineers implement and visually verify application-owned renderers using the development skill. |
| Tutor visual decisions | Compact runtime guidance supplies semantic awareness and honest scene references; no SVG, CSS, coordinates or timing. |
| Specialist composition | Future bounded capability pack proposes semantic content only after authorized dispatch; disabled in this task. |
| Renderer/application | Own exact registered IDs, layout, rendering, motion, validation, safety/permissions, Scene acceptance and persistence. |

The development skill is not runtime capability. Runtime models receive only
explicitly loaded, versioned subsets. Rendering, requesting, repeating or liking
a scene does not prove learning benefit. Canvas has no direct Evidence, Personal
Facts or Learning Intelligence authority.

## Representation follows the instructional relationship

| Representation | Use / limits |
|---|---|
| Chat-only | Valid whenever a visual adds no learning value, a capability is unavailable, or current evidence is insufficient. |
| Known exact activity | Prefer when objective and exact content fit; preserve its server-owned validation. Do not replace precise accepted exercises with approximations. |
| process_sequence | Directional stages of a supported process, language writing/revision, or procedure; do not imply a return. |
| process_cycle | Only source-supported return relations. Butterfly adult → egg means reproduction/new generation, not the same individual becoming an egg. |
| labeled_diagram | Parts and supported relationships; not a graded identification activity without a validation authority. Planned, not enabled here. |
| geometry_scene | Explain labels versus separately constrained manipulation; application owns mathematical constraints and coordinate direction. Planned, not enabled here. |
| quantity_visual / fraction | Explicit whole, partition, value and conservation invariants. Mathematical fractions keep real fraction notation; ordinal stage progress does not. Planned, not enabled here. |

No novelty-driven selection, arbitrary circularization of scientific processes,
new per-lesson components, or closed exercise catalogue. Sequence and cycle are
variants of the reusable Process family, not separate services.

## Composition and visual writing

Use illustration first where it conveys meaning. Give relations spatial weight:
clear paths, direction and meaningful return, not tiny arrows between generic
cards. Cards support details; they do not replace the primary spatial scene.
A cycle should read as a cycle before all text is read; a sequence communicates
direction. Use a restrained consistent palette, whitespace and hierarchy suitable
for learners roughly 10–18. Keep the center restrained.

Primary labels are concise names, not permanent paragraphs. Longer explanation
belongs in focused DOM callouts or Tutor Chat. For example, “Chrysalis” labels
the object; “The butterfly develops inside the pupa” belongs in its selected detail.
Use “Stage N of M” / “المرحلة N من M” for ordinal progress, never N/M. Do not
change real mathematical/scientific symbols merely to satisfy this ordinal rule.

SVG owns spatial symbols/relations. Application-rendered DOM text is preferred
for shaping, wrapping, accessibility and longer copy. Text must not be baked
into illustrative pixels. No model-authored HTML/JS/SVG, path code or callbacks.

## Semantic motion and interaction

| Vocabulary | Meaning and equivalent |
|---|---|
| FOCUS_OBJECT | Ring/shape and explicit focus label identify the semantic object. |
| DEEMPHASIZE_OTHERS | Reduce competing illustration emphasis without hiding context or making labels unreadable. |
| REVEAL_OBJECT_DETAIL | Show relevant detail while retaining orientation. |
| TRACE_RELATION | Follow a declared relation in its actual direction; static equivalent retains full highlighted path and arrow. |
| TRANSITION_FOCUS | Change semantic focus without rebuilding the Scene or changing object identities. |
| MOVE_ALONG_RELATION | Future use only when movement itself explains the relationship; not decoration. |
| Conserved grouping/partition transition | Future quantity use only while preserving whole/partition/value equivalence, with domain validation. |

Motion communicates attention, relationship, sequence, transformation or conserved
equivalence. No decorative bounce/spin/particles/continuous loops. Native CSS/SVG
is accepted for the current bounded vocabulary. Motion is deferred; authorized
candidate status alone does not add a dependency. Application owns easing/duration,
interruption and cancellation; Tutor/specialist do not author a narrated timeline.

Click/tap and semantic focus are primary; hover enhances only. Keyboard offers
equivalent operations and visible focus. IDs are authoritative; pixels and
browser-only state are presentation, not durable truth. Use non-color state
signals and meaningful text equivalents. Reduced motion preserves all information
with immediate focus, detail and complete relation emphasis.

## Arabic, responsive layout and assets

RTL prose does not automatically reverse causal or mathematical direction. Use
explicit bidi isolation for mixed labels; mathematical coordinates remain domain
owned. Wide spatial layouts may become deliberate narrow spatial arrangements
with explicit cycle return. Never merely shrink desktop until labels are unreadable.
Inspect long labels for collisions with symbols, paths and supporting captions.

Reuse approved task-owned illustration handles. External assets require provenance,
rights, content review and permission through existing storage boundaries. Optional
generated images are separately gated referenced illustrations, never scientific
or mathematical truth. No private learner history, names or responses in reusable
content. No provider activation or new asset pack follows from this guide.

## Good / bad evidence and inspection

| Bad direction | Accepted direction / evidence |
|---|---|
| Cards/rows/stacks as the primary cycle | [Checkpoint 1](reviews/STUDIO-VISUAL-PROCESS-01/VISUAL_CHECKPOINT.md) preserved as rejected cycle language; [Checkpoint 2](reviews/STUDIO-VISUAL-PROCESS-01/VISUAL_CHECKPOINT_2.md) replaces it with radial SVG and meaningful paths. |
| Permanent paragraph at every node | Concise stage labels with focused DOM detail in the accepted gallery. |
| Decorative spinning/pulsing | TRACE_RELATION drawing only along the declared relation; verify initial/intermediate/final frames and interruption. |
| Fraction-like stage counter | Accepted closure uses Stage N of M / المرحلة N من M with restrained size. |
| Same butterfly returns to an egg | Dashed, captioned next-generation return; source-supported reproduction. |

Inspect actual rendered screenshots, not just JSON/DOM checks. Review initial,
intermediate and final motion states, default/focused/detail, wide/narrow,
Arabic/English/mixed, long labels, keyboard and reduced motion. Fix overlapping
labels, weak arrowheads and misleading relations. Prepared-data proof does not
prove natural generation or pedagogical quality. Product decisions are required
for new representations, authority changes, unsupported scientific relationships,
new dependencies or work beyond the active authorization.
