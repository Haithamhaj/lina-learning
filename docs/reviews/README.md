# Review and acceptance evidence

`docs/reviews/` contains non-authoritative review evidence and acceptance provenance. It can prove what was observed at a historical checkpoint; it does not define current product behavior, execution authority, or architecture. Read canonical documents and code/current state for those.

New review records may use `docs/reviews/<TASK-ID>/`. Keep acceptance, implementation, and Product Owner decisions distinct. Private raw evidence and secrets remain outside the repository.
