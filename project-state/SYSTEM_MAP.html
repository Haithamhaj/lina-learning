Learning Studio — Target Architecture

The FE-02 Daily Student shell is a preserved prototype, not accepted production Studio architecture. Durable Studio State, Subject Capability, authenticated resumable Protocol, Tutor Snapshot/Event observation-watermark, WorkspaceIntent, and the deterministic Workspace Router are implemented; activities, renderers, and FE-02 production integration remain incomplete.

StudentUses Chat and/or Canvas. Chat remains usable when any Studio work fails.
Chat and/or CanvasSimple student-facing surfaces; neither is Studio authority.
Studio CoreTarget application-owned authority for semantic Event Log, Materialized Snapshot, authorization, Safety/Parent Boundary, scene versions, idempotency, cancellation, stale-result rejection, resumable Studio feed, and routing.

Implemented foundations cover durable state, exact subject capability contracts, authenticated protocol transport, one-primary-call Tutor access to the current Snapshot plus exact unseen Events, and deterministic Workspace decisions. Routed decisions do not render a Canvas or mutate Studio state.

TutorSole teaching authority; sees compact Studio snapshot/history and emits semantically meaningful Studio intents.
Deterministic Workspace RouterIMPLEMENTED: decision-only active Scene, authorized Source/Annotation, known-capability, custom-compose eligibility, and fallback routing.
Optional Canvas Specialist — CUSTOM_COMPOSE onlyNOT IMPLEMENTED. The Router may record eligibility only; no specialist model, provider, tools, or ScenePlan execution exists.
Subject Capability LayerIMPLEMENTED: exact Subject/Activity/Renderer/Action/Validator contracts and typed validator/reducer dispatch; no production Activities or renderers.

Tutor SSE remains the Chat conversation feed. The implemented Studio Feed is authenticated resumable workspace state, not a second chat stream or raw Chat replay. Tutor context observation/watermark, WorkspaceIntent, and the Execution Router are implemented; Canvas-originated Tutor turns, Student-facing activities/renderers, Canvas Specialist execution, and FE-02 production integration do not yet exist. Canvas actions and derived Vision outputs do not create Evidence directly. All later Studio work stays dependency-ordered and blocked.
