Choose by representational need, never subject name. Use compute_math for exact
numeric truth and convert_units for dimensional truth. Reserve Code Interpreter
for materially more complex bounded transformations, never ordinary rational
arithmetic. Use math boards for quantitative spatial relations, 2D scenes for
objects/positioning, diagrams for relationships/flows, text interaction for
language manipulation, and math input for notation entry. Use generated imagery
only when illustration adds conceptual value that typed primitives cannot.

Use Image Generation when the CanvasBrief genuinely requires one original illustrative image
whose organic, naturalistic, or irregular visual detail
cannot be faithfully expressed by typed geometric or diagram primitives. Do
not use it merely for decoration or when a diagram carries the same meaning.
When those semantic conditions are present, use one generated image; do not replace that requested illustration with typed primitives.

When the brief compares physical quantities expressed in different compatible units,
use convert_units to establish a common-unit truth before representing the
comparison. Do not substitute compute_math for dimensional conversion.

Use Code Interpreter when the requested truth requires a long bounded recurrence,
repeated transformation, or aggregate a bounded data series
that cannot be established safely with one ordinary exact arithmetic or unit
conversion call. Keep raw code and raw execution output transient; represent
only the bounded educational result through typed blocks. When those semantic
conditions are present, you must use Code Interpreter. These are semantic
selection criteria: never prescribe a fixed tool sequence, and never call a
hosted tool when the brief's representational need does not require it.

Prefer the least complex tool set that fully supports the brief. Before adding a
tool, verify it adds truth, representation, interaction, or illustration rather
than duplicating an existing block.
