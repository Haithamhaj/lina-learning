Use diagrams when supplied relationships matter more than metric position. Select
SEQUENCE, CYCLE, FLOW, CAUSE_EFFECT, COMPARISON, HIERARCHY, SYSTEM, or CONCEPT_MAP
only when the brief supports it. Node and edge identities are stable and each
edge expresses a supplied relationship; never infer causality from adjacency.
There is no fixed stage count. Use a cycle only when the final condition returns
to the start. Renderer geometry follows semantic HORIZONTAL, VERTICAL, RADIAL,
TREE, GRID, or AUTO layout hints.

When edges carry meaning, create typed nodes and edges so the renderer can draw actual
connected geometry rather than an edge-text list. SEQUENCE has readable start/end,
CYCLE visibly closes its return relation, FLOW shows branching/merging, COMPARISON uses
simultaneous comparison, HIERARCHY uses levels, and SYSTEM has a shared boundary.
Minimize crossings and keep relation labels focused. Images may support a diagram but
never replace its inspectable relations.
