# CURR-RENDER-MATH-01 — Validator Map

**Principle:** deterministic subject validation checks bounded mathematical state. It does not become a generic tutor, select pedagogy, decide safety, invent source facts, or over-constrain a legitimate alternative method. `Reference-grounded` means a later source/context check may be needed for a word-problem interpretation; it is not a reason to invent an LLM validator call.

| Validator concept | Used by concepts/renderers | Inputs → outputs | Kind / partial progress | Must accept | Must not over-constrain |
|---|---|---|---|---|---|
| `numeric_relation_validator` | number line, decimal comparison/rounding, estimates | value(s), operator/range/rounding place → relation, expected interval/value, explanation code | deterministic; validates selected interval/point before final answer | exact decimals/rationals and declared tolerance where visual snapping applies | a pixel coordinate, one wording, or only one estimate strategy |
| `place_value_state_validator` | place-value workspace, decimal operation bridge | place assignments, digits, target representation → valid state/value/next options | deterministic; yes | equivalent expanded forms and zero placeholders when mathematically valid | a single drag path or a particular order of filling cells |
| `arithmetic_decomposition_validator` | area/array, product estimate | factors, partitions, partial products, total → valid partitions/subtotals/result | deterministic; yes | any correct distributive decomposition and commuted factors | the standard algorithm or a pre-authored partition alone |
| `division_state_validator` | long-division workspace | dividend/divisor, quotient chunks, subtraction rows, bring-down sequence, decimal policy → valid/invalid/under-specified + next valid states | deterministic; yes | partial quotients and standard algorithm variants that conserve dividend = divisor × quotient + remainder | one quotient-chunk size, cosmetic layout, or a forced instructional sequence when multiple paths are valid |
| `fraction_structure_validator` | fraction model workspace | whole identity, partitions, shaded/allocated units, operation/target → validity/equivalence/result | deterministic; yes | equivalent fractions, different common denominators, equivalent area/bar states | an assumed whole, unequal parts, color pattern, or a single model form |
| `fraction_operation_validator` | fraction addition/subtraction/multiplication/division | operands, operation, method state, answer → result/equivalence/explanation code | deterministic; yes | reducible and unreduced answers when task allows; multiple valid methods | mandatory simplification unless stated, one denominator path, or a model that hides the whole |
| `unit_conversion_validator` | measurement/data workspace | source value/unit, destination unit, conversion relationship → converted value/dimension match | deterministic; yes | equivalent units and fractional/decimal result forms | conversion between unlike dimensions or a locale-specific unit spelling as math truth |
| `line_plot_state_validator` | measurement/data workspace | scale, observations, plotted marks, question → plot validity/counts/derived answer | deterministic; yes | repeated values and any mark order | one screen position, color, or visual packing order |
| `volume_state_validator` | volume composer | dimensions, occupancy/layers, decomposition, unit cube → no-gap/no-overlap state, volume, additive total | deterministic; yes | different non-overlapping rectangular decompositions and formula forms | a 3D gesture path, a single orientation, or “counting” that is actually hidden geometry |
| `coordinate_state_validator` | coordinate plane | axes, scale, point(s), labels → coordinates/set equality/tolerance | deterministic; yes | exact grid location and point order where order is irrelevant | pixel precision beyond snap tolerance, display orientation, or only one label spelling where localization differs |
| `shape_property_validator` | shape property explorer | shape definition/properties, category graph, learner labels/sorts → property truth/category membership | deterministic; yes | multiple correct category paths and inclusive hierarchy membership | visual resemblance, rotation, scale, or one informal name when a precise property is accepted |
| `expression_pattern_validator` | expression/pattern | parsed expression/rule, sequence inputs/outputs → equivalence/pattern result | deterministic; yes | equivalent syntax/commutativity and alternative rules with same bounded truth table when task permits | formatting, token order that preserves semantics, or an input method |
| `contextual_answer_validator` | word problems across families | source question, extracted quantities/units, candidate model/answer → bounded consistency status | reference-grounded; partial only when quantities are unambiguous | mathematically valid solution paths and explicit assumptions | choosing the intended interpretation when the source is ambiguous; this needs Tutor/source clarification |

## Validator contract recommendations

- Return a **typed status** such as `VALID`, `INVALID`, or `UNDER_SPECIFIED`, with safe feedback codes and valid next actions—not an unbounded natural-language lesson.
- Preserve the submitted state and causal renderer revision so Tutor can understand a meaningful attempt later. Raw Student work/original image remains separate source authority.
- Version validators and fixtures with their capability; a changed validator must be testable against prior valid and invalid states.
- For visual input, define tolerance in mathematical units (for example, grid increment), never opaque screen pixels.
- A subject validator is invoked through the future Subject Capability boundary. Studio Core sees only result status and generic lifecycle semantics.
