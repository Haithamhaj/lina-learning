# CURR-RENDER-MATH-01 — Open Questions and Gates

## Blocking before renderer implementation

1. Product Owner must promote a specific, bounded implementation task; this research pack is non-authoritative.
2. The future Studio Core event/snapshot, Subject Capability, validator dispatch, accessibility, and failure contracts must be authorized before any interactive renderer writes durable state.
3. Each `EVALUATE BEFORE CUSTOM BUILD` reuse-catalog item relevant to the selected slice needs an `ADOPT`, `PARTIAL ADOPT`, or `REJECT` record. Current direction does not authorize a package install.
4. A first renderer must have an explicit learner outcome, fixture set, validator contract, and accessibility/mobile acceptance criteria.
5. Rights review must approve any source asset before content ingestion, copying, adaptation, or runtime use; research links alone are not permission.

## Non-blocking

- Exact McGraw edition and pacing are not required to preserve the concept/renderer catalog.
- No textbook copy, Khan content, or MLC app code is needed for a useful foundation.
- Full Grade 4/6 curriculum research is unnecessary; cross-grade labels are estimates for prioritization.
- A Canvas Specialist, generated image, Vision, rich 3D, JSXGraph, Konva, and MathLive are not prerequisites for a deterministic React/SVG proof.

## Requires Product Owner decision

1. Select the first implementation proof objective and initial renderer batch from [06_COVERAGE_AND_PRIORITY.md](06_COVERAGE_AND_PRIORITY.md); this pack recommends `number_line`, `place_value_workspace`, `fraction_model_workspace`, and `long_division_workspace` but does not authorize them.
2. Confirm whether the first proof must exercise a separate Studio feed/event history or begins with a display-only renderer. Studio research recommends the application-owned event/snapshot boundary for meaningful interaction.
3. Define which committed semantic actions are Tutor-visible StudentInteraction and which remain record-only; they must not automatically become Learning Intelligence evidence.
4. Decide the source-asset approval workflow for the future Trusted Educational Reference Pack, including commercial product posture.

## Requires book / McGraw data

- exact edition/year/ISBN and volumes;
- table of contents, sequence, school pacing, and local vocabulary;
- authorized source provenance and any license/access conditions;
- the small set of real page/handwriting patterns that would justify a reconstruction configuration.

## Requires proof spike

1. Plain React/SVG versus JSXGraph for a specific coordinate/geometry interaction.
2. Plain React/SVG versus constrained Konva only if spatial cube/annotation editing cannot meet a11y/mobile acceptance.
3. Native controlled input versus MathLive for a defined expression-entry task.
4. The event/snapshot/reconnect behavior for one deterministic interactive activity, including cancellation, stale rejection, and Tutor observation watermark.

## Requires real Lina use

- Whether visual/interactive representation actually clarifies the concepts where this map predicts high value.
- Whether Lina prefers bars, number lines, grids, or concise notation for a given state; this should inform Tutor choice, not turn a static preference into authority.
- Whether the initial batch's support level, interaction friction, touch targets, Arabic/English/mixed-language behavior, and accessible text alternatives work in natural homework use.
- Whether photo side-by-side/annotation/reconstruction adds enough value to justify the separately gated Vision path.
