# A2 — Stable Prefix / Dynamic Suffix review (2026-09-28)

## Decision

**KEEP CURRENT STRUCTURE.** A2 made the exact shared text prefix substantially longer, but did not increase provider-reported cross-turn cached tokens under the unchanged implicit cache mode. It passed every deterministic check in 46/60 Golden runs versus 48/60 for the current production order, mainly because it gave fewer useful learner next actions. It was modestly faster and cheaper in this run because it generated fewer output tokens. This small synthetic evaluation does not justify changing production Tutor ordering. No production code, model/JEV setting, reasoning effort, memory count, cache control, or deployment was changed.

## Exact structural design and source contract

The accepted 20 Golden Set pre-context fixtures were frozen. For both arms, the harness called the same production context-selection, `_payload_from_context`, `build_tutor_model_payload`, capacity guardrail, strict `tutor_turn_v12` schema, and OpenAI adapter. The top-level Tutor `instructions` and every non-`input` request field were identical. A2 parsed the **runtime-built** `input` by its existing section headings, failed if an expected heading/order changed, and moved whole sections without rewriting their text. Section separators gained at most one newline; no teaching rule or learner context was added or removed. Tests compare the parsed content of every section and the non-input request envelope across all 20 cases.

| Position | Existing sections in A2 |
| --- | --- |
| Top-level request | Unchanged Tutor role, teaching/Canvas/safety instructions and unchanged response schema. |
| Stable `input` prefix | TeachingMode, TeachingStrategy, TeachingMethod, and PriorMethodRelation definitions/calibration; Hidden Segment relation rules; Parent Boundary semantic rules. |
| Dynamic context | Core Profile → optional Personal Memory → retrieved curriculum → Learning Intelligence and optional prior Concept → Studio/Canvas state → visual catalogue state → Visual Need signal → optional age directive → effective Parent Boundary settings → prior persisted method → confirmed Segment State. |
| Dynamic conversation tail | Relevant older exchanges → recent exchanges → immediate exchange → optional suggested-action source → Candidate Event source link → Current Turn and current raw source ID. |

Parent Boundary *rules* are reusable; effective settings remain dynamic and server-owned. Studio and Visual Need blocks contain changing state and their existing attached guidance, so they stay in the dynamic suffix. All authority distinctions remain present. A2 neither moves Current Turn alone as A1 did nor adds a cache key or explicit breakpoint.

This design follows [OpenAI's official prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching): cache reuse needs an exact prefix, but a long matching substring inside a changing message is not necessarily an eligible cached breakpoint in implicit mode. The guide states a 1,024 visible-token minimum for GPT-5.6 and later and explains why implicit caching can write through a changing message rather than the stable substring within it. We deliberately did not add a breakpoint because this experiment isolates structural ordering.

## Golden Set method and quality

Each of the 20 synthetic cases ran three times per arm on `gpt-6-luna`, current reasoning default, and `recent_exchange_count=1`. Each baseline/variant pair was adjacent, with case-level A→B, B→A, A→B alternation and the reverse on the next case. The arms each went first 30 times. All 120 calls completed. The Visual Need fixtures, content, instructions, response schema, and provider settings were the same; only `input` section order differed.

### Pedagogical and authority review

- **Confusion and strategy:** A2 handled g03's explicit confusion well in this sample and both arms changed method in g04. g06 preserved `EXPLAIN_THEN_CHECK` in all three runs per arm. Across the full set, A2 selected that strategy twice less often and had four fewer next-action screen passes.
- **Unfinished learning:** In g05, production once leaves the tens calculation for the learner; A2 reveals the final answer in all three replies. In g07, both arms often answer their own rhetorical question rather than inviting a new attempt. A2 also loses a continuation action in g08 and g09.
- **Visual choice and wording:** Both arms request high-value Science visuals and the explicit requested visual, and avoid unnecessary or duplicate Canvas work. The authority regex catches two baseline early “look at the drawing” claims and none in A2. Human review also found an A2 “I prepared a drawing” claim in g04 and g10 before delivery; production makes a comparable “prepared” claim in g10. The regex result is therefore a narrower finding than complete Canvas-delivery fidelity. g14 pending Canvas language is truthful in both arms.
- **Personal Memory and history:** In g15, production naturally uses the synthetic mint detail in 2/3 replies and A2 in 1/3. Neither arm inserts irrelevant mint context into g16 math, and both follow the current ant preference over stale butterfly memory in g17. Both affirm the current independent answer in g18–g19 and honor g20's words-only request despite older visual preference. Neither arm treats mixed historical LI as more authoritative than the current correct answer.

These are reviewer judgments on synthetic outputs, with moderate confidence because there are only three samples per case. The deterministic counts and request invariants have high confidence for this run.

A2 was 394 ms faster on average in the 60 matched pairs (median −492 ms), faster in 34 pairs and slower in 26. It generated 2,816 fewer output tokens (5.4%) and its estimated Golden cost was $0.001408 lower (3.9%). The run is too small to establish a durable latency or cost effect; the cost difference here came from output, not cached-input improvement. Cost uses the harness's versioned local rates and provider-reported token categories, not an invoice.

## Two separate cache observations

**Repeated identical Golden prompts:** Both arms reported exactly 434,016 cached, 41,658 cache-write, and 180 ordinary input tokens across 60 calls. This schedule warms each identical case prompt. Its cached totals are **not** production cross-turn cache evidence.

**Changing-turn synthetic probe:** A separate three-turn plant-learning session changed the Current Turn and accumulated complete Exchange history while keeping the same Tutor instructions, schema, Core Profile, Personal Memory, and model. The session lineage remained stable and each Student turn had a distinct synthetic source ID. The exact common prefix within `input` grew from **381 characters under production** to **9,421 characters under A2** across all three turns (9,713 for A2 turns 2→3). That is a genuine longer text prefix. Nevertheless, on each changed turn 2 and 3, **both arms reported 5,845 cached input tokens**; both wrote 2,074 and then 2,170 tokens. A2 did **not** produce a measured cross-turn cache gain.

On probe turn 1, production went first cold (0 cached tokens), and A2 went second after the common top-level instructions had warmed (5,845 cached). That order-confounded difference is excluded from the cross-turn conclusion. The six probe calls cost an estimated **$0.004357175**. The complete A2 evaluation, Golden plus probe, cost **$0.074519995**.

The official guidance explains the observed limit: in implicit mode, writing the full changing user message does not guarantee a reusable breakpoint after the stable substring inside it. We did not add explicit breakpoints, message-role changes, or cache keys. A separate, explicitly scoped cache-control experiment would be needed before claiming a production cache benefit.
